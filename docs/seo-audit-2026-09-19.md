## 검증 방법

- `npm test`: canonical, 잘못된 경로, FAQ 범위, 구조화 데이터, 서비스 메타, AI 문서 동기화 회귀 테스트.
- `npm run lint`: TypeScript 검사.
- `npm audit`: 운영·개발 의존성의 알려진 취약점 검사. 2026-09-19 패치 후 0건.
- `npm run build`: 공개 1,294개 경로와 관리자 경로 생성.
- `npm run audit:seo -- --report=audit-final.json`: 모든 공개 페이지의 제목/설명 중복, canonical, H1, 초기 HTML, FAQ 일치, 내부 링크, 이미지, 입력란 label 검사.
- 배포 후 `npm run audit:seo -- --origin=https://www.neutiul.com --report=audit-production.json`: 같은 검사와 HTTP 404, 공개 파일 응답 검사. GET/HEAD만 사용하며 견적을 발송하지 않는다.

기준 빌드 검사: 제목 1,294개와 설명 1,294개가 각각 고유했고, 참조 이미지 445개는 모두 존재했다. 문제는 누락된 내부 연결과 실제 페이지에 맞지 않는 스키마에 집중되어 있었다.

최종 로컬 검사: 회귀 테스트 7개, TypeScript, 전체 빌드 통과. 공개 1,294개 페이지와 참조 이미지 445개, 내부 경로 1,295개(관리자 포함)를 검사해 오류 0건을 확인했다. 데스크톱 홈, 모바일 FAQ·지역 이동·문의 필수 입력 검증을 확인했다. 배포용 지역 HTML의 hydration도 정상이다. Vite preview에서는 정적 하위 경로 끝에 `/`를 붙여 열어야 해당 파일을 읽으므로, 이를 운영 서버의 문제와 구분한다.

## 운영자가 계속 관리할 사항

- Search Console/네이버 서치어드바이저에서 소유권·사이트맵 접수·실제 색인 상태를 확인해야 한다. 다른 사이트의 Google 인증 코드를 느티울에 재사용하지 않았다.
- 기존 화면의 경력·누적 실적·평점 문구는 원래 콘텐츠로 유지했다. 근거 자료는 별도 관리가 필요하며, 검증되지 않은 수치로 평점 스키마를 만들지 않았다.
- 지역 페이지는 상담 가능 지역 안내다. 지역별 실제 현장 사례·사진·고유 설명이 축적되면 보강해야 하며, 지역명만 바꾼 페이지 수 증가가 검색 품질을 보장하지 않는다.
- 주소·전화·영업시간은 실제 운영 정보와 계속 일치시켜야 한다. 확인하지 못한 정밀 좌표·우편번호는 제거했다.
- llms.txt는 보조 안내 파일이다. 별도 AI 전용 마크업이나 meta keywords만으로 검색·AI 추천 순위가 오르지는 않는다.
- 실제 고객에게 이메일을 발송하는 테스트는 수행하지 않았다.

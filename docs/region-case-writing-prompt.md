## 1. 사진 고르기

1. **출처**: 구글 드라이브 루트 폴더 한 곳의 사진만 씁니다. 폴더 이름의 지역/업종과 사진 내용이 맞는지 직접 확인합니다.
2. **이미 쓴 사진인지 확인**: 사이트의 기존 이미지와 비교해 같은 현장인지 확인합니다.
   - 비교 대상 폴더: `public/images/{services,reviews,about,portfolio-gallery,regional}`
   - 비교 방법: dHash, 해밍거리 8 이하이면 같은 사진으로 봅니다.
   - 다른 사례 글(`regional/`)과 겹치는 사진은 쓰지 않습니다.
   - 포트폴리오(`portfolio-gallery`)와 겹치면 같은 현장이라는 뜻입니다. 그 포트폴리오의 지역명이 맞는지 확인하고 `portfolioItemId`로 연결합니다.
3. **노출 금지**: 아래가 보이는 사진은 잘라내거나(크롭) 뺍니다.
   - 다른 업체·시설의 상호, 간판
   - 창밖 가게 간판, 전화번호가 적힌 현수막
   - 주소, 서류, 차량 번호판
   - 장비 상표
4. **장수와 변환**
   - 장수: 8~12장, 같은 사진 중복 없이
   - 변환: `sharp`로 `.rotate().resize(900,1200,{fit:'cover'}).webp({quality:80})`
   - 저장 위치: `public/images/regional/{regionId}-{service}-NN.webp`
5. **단계 표시(캡션 앞 배지)**
   - 작업 전 / 작업 중 / 작업 완료(또는 마무리 단계)
   - 도구나 물기가 보이면 "작업 중"입니다.
   - 완료 사진이라고 대표님이 확인해 주면 "작업 완료"로 씁니다.

## 3. 말투와 단어 (가장 중요)

- **대표님 1인칭 블로그 후기체**로 씁니다.
  - "저희가 ~하는 모습입니다", "~보여드리겠습니다", "~보이실 거예요", "~함께 말씀드립니다"
- **고객 눈높이 단어**를 씁니다. 전문 용어는 쓰지 않습니다. 장비 이름은 처음 나올 때 괄호로 쉽게 풀어 줍니다.

| 쓰지 말 것 | 이렇게 |
|---|---|
| 평걸레, 플랫 몹 | **맙(왁스 바르는 걸레)** |
| 폴리셔 세척 | 바닥 닦는 기계(폴리셔)로 때 벗기기 |
| 오염수 회수 | 더러운 물 걷어 내기 |
| 물밀대 | 물밀대(물을 한쪽으로 밀어 모으는 도구) |
| 코팅제 도포 | 왁스 바르기 |
| 교체 타일 색 차이 | 나중에 바꿔 끼운 듯 색이 다른 타일 |
| 반사가 올라옴 | 빛이 비칠 만큼 반짝임 |
| 공실 | 빈 사무실 (메타설명의 검색어 "공실·입주 전"은 예외) |
| 코팅층 아래 갇힘 | 얼룩 위에 왁스가 덮여 그대로 남음 |
| 면적·오염 정도·기존 코팅 유무 | 바닥 넓이·얼룩 정도·예전에 바른 왁스가 남아 있는지 |
| 천장 환기구(격자무늬 흰 커버 사진) | **에어컨 커버(뚜껑)와 그 안에 끼워진 먼지 필터** |

- **금지 표현**: 완전히 제거, 균일한 광택, 미끄럼 방지, 내구성, 완벽, 세척이 완료된, 개점 가능한
- **사진 속 장소 구분**: 사무실 안인지, 사무실 밖 건물 공용 복도인지 구분해서 씁니다. 사무실 청소 현장의 복도 물청소 사진은 대개 사무실 밖 공용 복도를 물청소한 장면입니다. 헷갈리면 대표님께 확인합니다.
- **불필요한 설명 금지**: "(건물명·정확한 주소는 비공개)" 같은 문구는 넣지 않습니다. 위치는 "인천 부평구 빈 사무실"처럼만 씁니다.

## 4. 글 구조 (`lib/regionCaseData.mjs`)

페이지 순서는 아래와 같고, 목차는 3개입니다.

1. 목차 (버튼형 3개)
   - ① 현장 기록 · 작업 내용과 사진
   - ② 작업 전 준비사항
   - ③ 자주 묻는 질문
2. **현장 기록**(`facts`) 4칸
   - 위치: "인천 부평구 빈 사무실"
   - 작업 전 상태: 사진으로 보이는 것만 씁니다.
   - 작업 순서: 쉬운 말을 `→`로 연결합니다.
   - 인원·시간: "이번 현장은 {N}명이 들어가 {N}시간 동안 작업했습니다."
     - 현장 규모를 보고 정하되, 대표님께 숫자를 확인받습니다.
3. **작업 내용과 사진**: 정확히 3개 섹션(`sections`)이고, 섹션마다 `stepIndexes`로 해당 사진 단계를 **글 바로 아래**에 붙입니다.
   - 작업 전 → 작업 중(닦기·헹구기) → 작업 완료 순서입니다.
   - 사진 단계(`steps`) 제목도 쉬운 말로 씁니다. 예: 작업 전 바닥 상태 / 기계로 바닥 닦기 / 더러운 물 걷어 내고 헹구기 / 맙으로 왁스 바르기 / 작업 완료 후 바닥
4. **작업 전 준비사항**(`prep`) 4~5개: 그 현장 사진에서 실제로 필요했던 것을 기준으로 정합니다.
   - 지금 바닥 상태를 사진으로 보여주세요: 고객 말투 예시("가구 뺀 자리에 동그란 얼룩이 남았어요.")로 시작합니다.
   - 예전에 왁스를 바른 적이 있으면 알려주세요: 잘 모르셔도 괜찮다고 덧붙입니다.
   - 짐과 가구 옮길 범위를 정해 주세요
   - 전기와 물을 쓸 수 있는지 확인해 주세요: 바닥 기계는 전기로 움직이고 물도 씁니다.
   - 왁스 마르는 시간과 다음 일정을 알려주세요: 입주·가구 반입·출근 일정에 맞춥니다.
5. **자주 묻는 질문**(`faq`) 정확히 4개
   1. "{메인 키워드}는 {지역} 어느 지역에서 상담할 수 있나요?" → 하위 지역, 전 지역 출장, 무료 방문 견적
   2. 현장 특성 질문. 예: 얼룩이 심한 바닥도 바로 왁스를 바를 수 있나요?
   3. 사진 관련 질문: 마지막 사진들이 작업이 끝난 모습인지, 작업 전 사진과 같은 곳인지. 같은 자리 비교 사진이 아니면 솔직하게 씁니다.
   4. "{지역} {현장} {서비스} 비용과 견적은 어떻게 정하나요?" → 확인 항목을 나열하고, 사진만 보고 정확한 금액은 말하지 않는다고 씁니다.
- 노란 안내 박스(`note`)는 쓰지 않습니다. 사진 한계 같은 내용은 FAQ로 돌립니다.
- `teaser`(다른 사례 목록에 보이는 한 줄)와 `thumbnail`(작업 완료 사진)도 채웁니다.

## 5. 마무리 절차

1. `node scripts/generate-region-case-index.mjs`를 실행해서 나온 `lib/regionCaseIndex.json`을 커밋합니다.
2. `tests/region-case-cluster.test.mjs`를 갱신합니다.
   - 사례 개수
   - 해당 서비스의 지역 순서
   - 포트폴리오 연결
3. 아래 검사를 모두 통과시킵니다.
   - `assertAllRegionCases`
   - `npx tsc --noEmit -p .`
   - `npm run build`
   - `node --test tests/*.test.mjs`
4. 임시 스크립트(`scripts/_tmp_*`)는 지우고 커밋합니다.
5. main에서 새 브랜치를 만들어 PR을 엽니다.
   - PR 본문에 사진 출처, 크롭·제외한 사진, 검증 결과를 적습니다.
   - 대표님이 배포하라고 하면 직접 main에 머지해 배포합니다(Hermes 검수 단계 없음). PR을 여러 개 쌓았다면 아래 PR부터 차례로 머지합니다.
6. 모바일(390px)·PC(1280px) 화면을 캡처해서 보여줍니다.
